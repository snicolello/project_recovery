# Basic Memory and QMD scoped evaluation gap list

Completed October 10, 2026, within the approved one-day limit. Two tools, nine synthetic Markdown notes, five hands-on scenarios. No product implementation.

**The useful gap is narrower than a new Obsidian connector.** Both tools already retrieve project context and support explicit project scoping. Basic Memory also supplies a working accepted-status filter and automatic indexing of edits. The remaining opportunity is a small recovery workflow that verifies authority and freshness and returns consistent evidence references. These five cases establish concrete workflow gaps; they do not establish demand for a separate product.

**Decision boundary:** review this gap list before deciding whether the full 40-case benchmark is worthwhile. It has not been started or approved. A gateway, adapter, real-vault pilot, and repository publication are also unapproved.

## What was tested

Basic Memory **0.23.2**, Python **3.12.14**, and QMD **2.8.3**, Node **24.13.0**, on this Windows workstation. Both used lexical search, separate copies of the same notes, explicit project scopes, and local indexes outside the vault. Embeddings, reranking, paid model calls, agent hooks, and live GitHub integration were excluded.

The scenarios were selected and inspected by the assistant, with a small stdio MCP client recording the calls. This was a guided tool exercise, not an autonomous agent accuracy benchmark or independent human review. Exact-name follow-up reads were deliberately used to inspect evidence. The test vault is unusually well structured: its project note already states the five recovery fields, and conflicting notes explicitly identify their status. Success here does not demonstrate recovery from a messy vault.

Sources for the findings are the executed [Basic Memory responses](basic-memory-results.json), [ready-index recheck](basic-memory-ready-recheck.json), and [QMD responses](qmd-results.json), identified below by scenario. All observed outcomes are executed/measured evidence; implications and suggested remedies are inferences. Broader product capabilities remain unknown outside the tested call paths.

## Written gap list

| Gap | Evidence from these runs | Smallest remedy to consider |
| --- | --- | --- |
| **Current source authority is not established by local metadata** | S2's accepted status and source revision were fixture text. Neither tested path verified an actual GitHub acceptance record. A local `status=accepted` value can select a note but cannot prove its approval. | Define trusted repository/acceptance references and a read-only verification step. Offline results should say current authority is unverified. Assess existing integrations before adding code. |
| **Freshness is eventually consistent, without an explicit stale result** | Both served 15 seconds after the file changed to 45. QMD's status response showed index information but did not identify this changed file; Basic Memory's response also lacked a stale verdict. | Establish an index-ready/refresh procedure first. If stronger guarantees matter, bind each recovery to checked source bytes and a captured generation, with an explicit incomplete result on drift. |
| **Evidence references are incomplete for the proposed contract** | Basic Memory returned paths, content, frontmatter and search timestamps. QMD returned document IDs, paths and line-numbered reads. Tested responses did not provide the complete combination of exact span, full content digest, verified acceptance revision, and authority verification time. | Specify a minimal evidence receipt and determine which fields can come from existing tools. Do not mistake an echoed revision or short document ID for GitHub verification. |
| **Basic Memory exposes more authority than a read-only recovery client needs** | Its advertised MCP surface included write, edit, move, delete and project-management tools. QMD's advertised surface was query/get/multi_get/status. We called no mutation tools. | Use an enforced host tool allowlist or a restricted serving surface for Basic Memory. Advice to avoid writes is not enforcement. Read-only operating-system controls were not tested. |
| **A recovery packet still needs a workflow** | S1 succeeded because a curated project note already held the answer. Basic Memory's context result linked further evidence without including those bodies. Neither exercise generated a uniform packet of fields, conflicts and unknowns. | Start with a small manifest and an explicit read/verify/assemble recipe. Determine whether that is sufficient before proposing a gateway. |

Two narrower usability findings also matter. Basic Memory's project-list call failed when no default project was configured; setting Atlas as the default made it succeed in the recheck. The first cold searches returned ordinary empty results before indexing caught up. These need setup/readiness handling, not a new retrieval engine.

QMD's S2 search snippet displayed `title: Queue Archive` as line 4, while `get` and the actual file put it at line 2. The search result's separate `line` field was 2. Treat the rendered snippet labels as unreliable in this fixture and fetch the source before citing exact lines. This is a bounded observation, not a general audit of QMD citations.

## What this changes about the project idea

**Basic Memory is the stronger reuse candidate for this particular continuity workflow:** accepted-status filtering and automatic edit indexing already work. **QMD supplies a smaller observed read-tool surface and direct line-addressed retrieval**, but its refresh procedure must be explicit for this use case. These are fit judgments from five scenarios, not a broad product ranking.

A plausible portfolio contribution is a documented recovery contract plus a small integration or upstream improvement around freshness and provenance. The evidence does not yet justify replacing either retrieval engine. Before considering a larger benchmark, decide which gap actually matters to your personal workflow: eventual freshness may be acceptable; verified GitHub authority may be essential. That choice determines what needs further testing.

Unknowns left intentionally open: autonomous agent behavior, semantic search quality, arbitrary vault layouts, shared-client efficiency, repeatability across rebuilds, live GitHub status, Obsidian Sync conflicts, and adoption by other users. None has been converted into an assumed product deficiency.

## Environment and source integrity

The first Basic Memory executable launcher failed in this workspace; invoking its installed Python entrypoint worked. MCP startup inside the restricted sandbox then stalled in Python's internal socket-pair setup. The unchanged package ran successfully outside that sandbox. These are environment observations and are not counted as competitor recovery failures.

Both runtime copies matched the original nine-file hashes before the scenario runs. Afterward, the only changed source in each was the deliberately edited Atlas runbook; see [Basic Memory source check](basic-memory-source-check.json) and [QMD source check](qmd-source-check.json). Basic Memory permalink changes and auto-updates were disabled for the evaluation. This demonstrates source preservation in this configuration, not that its default server is read-only.

No real Obsidian vault, GOM mandate, SWIM USA repository, global MCP configuration, or existing project repository was changed. Temporary MCP processes were stopped. Pinned installations and logs remain inside this chat's workspace for reproducibility.
